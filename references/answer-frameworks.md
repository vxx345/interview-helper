# 思考框架库

供 SKILL.md「🧭 思路引导段」的「框架选择」步骤使用。先判断题型，再选框架，并显式告诉用户为什么选它。

## 审题三问（先做完 SKILL.md 的「Step 0 题型判定」，再走这三问）

1. **表面问什么 / 实际考什么能力？**
   例：「MySQL 为什么用 B+ 树」表面考数据结构，实际考「是否理解磁盘 IO 与树高的关系」。
2. **面试官想听到哪几个关键词？漏了哪个必然被追问？**
   每道题挑出 2–3 个「不听到就扣分」的关键词，写进记忆卡。
3. **要不要挂项目？** → 以 SKILL.md「Step 0 轴一」判定为准，**不是默认要挂**；口诀：**问「你」就挂项目，问「它」就不挂**。
   > ⚠️ 最高频错误 = 客观题硬挂项目（答原理补一句「我在项目里用过」→ 暴露背八股 + 硬套经历）。客观题的深度在机制层与边界层，不在个人经历。

## 六个思考框架

### 1. 分层法（自顶向下）
- **适用**：系统设计题、架构题、组件设计题（「设计一个 XX」「XX 的架构是怎样的」）
- **展开维度**：接入层 → 网关层 → 服务层 → 存储层；或 客户端 → 服务端 → 基础设施
- **变体**：**事前 / 事中 / 事后** 三层，特别适合容错、安全、一致性类问题
- **为什么好用**：天然体现「体系化」，且不容易漏层

### 2. 时间线法
- **适用**：故障排查题、链路问题（「线上 XX 慢了」「XX 不一致怎么排查」）
- **展开维度**：发生 → 发现（监控告警）→ 定位（链路追踪/日志）→ 止损 → 根因 → 复盘改进
- **关键加分点**：先止损再查根因；复盘要有可落地的 action item
- **为什么好用**：符合真实故障处理流程，能自然带出可观测性

### 3. 对比权衡法
- **适用**：选型题、「XX 和 YY 有什么区别」「为什么选 A 不选 B」
- **展开维度**：先列对比表格（一致性 / 性能 / 复杂度 / 运维成本 / 生态），最后**必须给选型结论**并说明前提
- **致命陷阱**：只罗列差异不给结论，等于没答。结论要带前提——「在 QPS 低于 X 且团队规模小于 Y 时，我选 A」
- **为什么好用**：表格可视化强，且能展示 trade-off 意识

### 4. 第一性原理法
- **适用**：原理题、底层题（「XX 是怎么实现的」「为什么需要 XX」）
- **展开维度**：它要解决什么矛盾 → 用了什么机制解决 → 这个机制的代价和边界是什么
- **关键加分点**：**说出机制的代价**。说得出代价才像真懂
- **为什么好用**：避免背诵式回答，自然带出设计权衡

### 5. 瓶颈定位法
- **适用**：性能题、容量题（「扛不住怎么办」「怎么优化」「为什么慢」）
- **展开维度**：先量化定位瓶颈在哪（CPU / IO / 锁 / 网络 / GC）→ 再谈优化手段（缓存 / 异步 / 批量 / 分片 / 池化）→ 最后兜底（限流 / 降级 / 扩容）
- **致命陷阱**：不问量级直接说「加缓存加索引」，属于典型背八股
- **为什么好用**：体现「先度量后优化」的工程素养

### 6. 约束拆解法
- **适用**：开放式设计题（「设计一个短链系统」「设计一个延迟队列」）
- **展开维度**：先反问约束（数据量级 / QPS / 一致性要求 / 延迟要求）→ 再选存储与中间件 → 最后谈扩展、容灾、降级
- **关键加分点**：**开口先问约束**。这一步大多数人直接跳过
- **为什么好用**：把开放题收敛成有边界的工程题

## 题型 → 框架速查表

| 题干特征 | 题型 | 首选框架 | 备选 |
|---|---|---|---|
| 「设计一个…」 | 系统设计 | 约束拆解法 | 分层法 |
| 「…的架构/组成」 | 架构描述 | 分层法 | — |
| 「为什么慢/扛不住/怎么优化」 | 性能 | 瓶颈定位法 | 时间线法 |
| 「线上…故障/不一致/丢了」 | 故障 | 时间线法 | 分层法 |
| 「A 和 B 的区别/怎么选」 | 选型 | 对比权衡法 | — |
| 「XX 的实现原理/为什么会」 | 原理 | 第一性原理法 | 分层法 |
| 「怎么保证/如何兜底」 | 容错 | 分层法（事前/事中/事后） | 时间线法 |
| 「说一个你做过的…」 | 项目 | STAR（见 reverse-qa.md） | — |

> 📈 **深度升级**：上表中「选型」「原理」「系统设计」三类题，在大厂 Agent / 后端岗常被追问到面委级深度。
> 但方案对比 / 架构 / 开放式题 **不自动升档**——升 `[深潜]` 仅当用户显式要求深度或 `mock:` 压轴题（口径同 SKILL.md「轴二」，勿放宽）；升档后走 `deep-dive-framework.md` 的六维框架。

## 高频陷阱清单（写进「考点与陷阱」段）

| 陷阱 | 表现 | 破法 |
|---|---|---|
| **客观题硬挂项目** | 答「volatile 的作用」时补一句「我在项目里用了 volatile」 | **删掉**。客观题深度靠原理链 + 论文引用 + 量化数据，不靠经历 |
| **停在 L1 就收工** | 「因为 B+ 树矮所以快」——没说为什么矮；只给结论和优点，没有机制解释 | 补「为什么」这条机制链（扇出大→树高 3 层→3 次 IO），并说出代价与边界 |
| **只有定性没有数字** | 「性能提升很多」「成本高不少」 | 换量级表述：P99 从**约 800ms 降到 100ms 量级**（业界通常情况）；成本差距**数十倍量级** |
| **编造论文 / 数据** | 给不确定的精确数字或论文编号（如「准确率 91%」却无出处） | **先联网检索核实**；查不到就改量级描述并标注「公开研究显示 / 量级估算」。**宁可模糊，不可编造** |
| **编造经历** | 虚构项目数据 | 用「业界通常做法」替代，或明确说「这是公开的大厂实践」 |
| 被追问就崩 | 追问是主战场，多数人只准备第一层 | 每段答案预埋一个「可往下钻」的钩子 |
