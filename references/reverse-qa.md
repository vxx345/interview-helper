# 反问环节 / 自我介绍 / 项目包装

当用户问「我该反问什么」「怎么做自我介绍」「项目怎么讲」「帮我改简历项目描述」时读取本文件。

---

## 一、反问环节话术库

选 2–3 个问，**不要全问**。反问是最后一次展示专业度的机会，问得好加分，问得差直接减分。

### 业务技术向（最推荐，显专业性）
- 「这个岗位所在团队，目前技术栈里自研组件和开源组件的占比大概是怎样的？」
- 「团队现在最棘手的技术挑战是什么？是稳定性、成本、还是迭代效率？」
- 「这个业务的高峰 QPS / 数据量级大概是什么规模？」
- 「现在的服务部署形态是怎样的？容器化到什么程度了？」

### 成长向
- 「您觉得在这个团队做得好的人，通常具备什么特质？」
- 「新人入职后前三个月，一般会负责什么类型的工作？」
- 「团队里有没有技术分享或 Code Review 的机制？」——顺带打听工程文化

### 避雷向（判断加班 / 稳定性）
- 「团队日常的迭代节奏是怎样的？发版频率大概多久一次？」
- 「遇到线上故障，一般是怎么响应和复盘的？」

### ⚠️ 忌问清单

| 问题 | 为什么忌问 |
|---|---|
| 薪资、加班费、几号发工资 | 留给 HR 面，问技术面试官显得格局小 |
| 能不能远程、能不能准时下班 | 等于当面问「我会不会很累」 |
| 网上一搜就有的问题（公司成立时间、主营业务） | 显得没做功课，直接暴露准备不足 |
| 「我今天表现怎么样」 | 把面试官架在火上烤，他没法回答 |
| 连续追问负面信息 | 面试是双向选择，但别把气氛搞成审讯 |

## 二、STAR 包装法（项目经历）

| 要素 | 回答什么 | 常见错误 |
|---|---|---|
| **S**ituation 情境 | 业务背景是什么，当时面临什么具体问题 | 铺垫太长，讲了三分钟还没进入正题 |
| **T**ask 任务 | 你负责哪一块，目标是什么 | 说「我们团队做了…」而说不清自己做了什么 |
| **A**ction 行动 | **你**采取了什么动作，技术选型是什么，为什么这么选 | 只罗列技术名词，不讲决策依据 |
| **R**esult 结果 | 量化的收益 | 「性能提升了很多」——没有数字 |

### 反面示范
> 「我们项目用了 Redis 做缓存，还用了 MQ 解耦，整体架构是微服务，我用 Spring Cloud 做的。」

问题：全是名词堆砌，没有具体问题、没有决策依据、没有结果。**这是最容易被挂的表述方式。**

### 正面示范
> 「订单超时未支付需要自动关闭，最初用定时任务每分钟扫全表（S），量上来后扫描耗时从 200ms 涨到 8 秒，影响主库（T）。我评估了三种方案：Kafka 延迟消息、RocketMQ 延迟消息、Redis ZSet 轮询。因为团队已有 Redis 集群且延迟精度要求不高（分钟级），我选了 Redis ZSet，用订单创建时间戳做 score，定时取 topN 处理（A）。上线后扫描耗时降到 50ms 以内，主库压力下降约 90%，且支持水平扩容（R）。」

好在哪：有具体问题 → 有方案对比和**选型理由** → 有量化结果 → 主动交代了 trade-off（精度要求不高）。

### 三层追问应对（讲完项目必被问）

1. **「为什么不用 XX？」** → 不要贬低 XX，要给**场景适配性**理由：「XX 在延迟精度要求高的场景更合适，我们这里是分钟级，引入一个新中间件不划算。」
2. **「有什么坑？」** → 主动说 1–2 个真实踩过的坑。这是**加分项**，说没坑反而显得没真做过。
3. **「还能怎么优化？」** → 给 1 个可落地的演进方向，说明前提条件：「如果量再涨一个量级，我会考虑拆成按 user_id 分片的多队列，不过现阶段复杂度不划算。」

## 三、自我介绍（1–2 分钟）

结构：**我是谁 → 我做过什么（挑 1–2 个最亮眼的项目，用 STAR 压缩版）→ 我为什么来这**。

### 埋钩子技巧
自我介绍的最后一句，主动抛出一个你**准备好深挖**的技术点，把面试官往你的主场引。

例：
- 后端方向：「最近在做一个 **Redis 延迟队列** 的改造，把原来的扫表方案换掉了，如果感兴趣可以展开讲讲。」
- Agent 方向：「我最近在做一个 **Agent 工具调用容错** 相关的事，踩了不少坑，可以聊聊。」

> ⚠️ **以上是「格式示例」，不是用户真实经历。**
> 生成自我介绍时，**必须先确认用户真实项目**（读你本地的「真实项目 FAQ 文件」或向用户询问），
> 再用同样的句式套到真实项目上。**禁止把这些示例直接写进用户的自我介绍**——
> 面试官会顺着钩子深挖，编的经历一问就穿。

**原理**：面试官 90% 的概率会顺着你埋的钩子往下问。**面试的主动权是可以设计的。**

### 时间分配
| 时长 | 内容 |
|---|---|
| 前 15 秒 | 基本信息 + 求职意向 |
| 中间 60 秒 | 1–2 个项目，用 STAR 压缩版，带数字 |
| 后 15 秒 | 埋钩子 + 表达对这个岗位的兴趣 |

## 四、面试尾声的三个贯穿原则

1. **框架化 > 背八股**：本质 → 方案 → 边界 → 案例。能说出「边界」的候选人不超过两成。
2. **追问才是真正的战场**：第一层问题大家都会，拉开差距的是第二、第三层。每段答案主动预埋一个可往下钻的钩子。
3. **工程判断力 = 知道「默认值不是最优解」**：敢说「我们把 RR 降到了 RC」「我们没用 Kafka 做延迟队列」，并给出理由——这才是资深和初级的分水岭。
