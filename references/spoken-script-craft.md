# 口述稿改写手册

供 SKILL.md「🎤 口述稿段」使用。目标：把书面答案改成**能直接开口念、念出来像人话**的逐字稿。

> ⚠️ 🚫 客观题（禁挂项目）的逐字稿同样禁用第一人称（「我在项目里…」「我踩过这个坑」），改用「通常的做法是… / 业界一般是… / 公开研究显示…」；完整规则见 SKILL.md「Constraints」。

口头表达和书面表达是两套语言。面试挂掉的人里，有相当一部分是「想得清楚但说不利索」——句子太长喘不过气，术语连发音都别扭，讲完没有收束。

## 一、书面 → 口语的 8 条规则

1. **单句不超过 25 字**。中文口语里，超过 25 字的句子听众就跟不上了。长定语从句一律拆成两句。
   - 书面：「通过引入读写分离架构来解决单库在高峰期面临的读压力瓶颈问题」
   - 口语：「单库扛不住读压力了。所以引入读写分离，把读流量分出去。」

2. **术语与项目专有名词首次出现补一句口语解释**。用「也就是说…」起头，顺便给自己争取 2 秒思考时间。
   - 通用术语：「用 MVCC，也就是多版本并发控制，让读写不互相阻塞。」
   - **项目专有名词（类名 / 字段名 / HAR / `${step.field}` 等内部缩写）同样要配白话**——面试官没看过你的项目：「参数会填成 `${stepN.field}` 这种引用，意思就是『取第 N 步返回的某个字段』，执行时才去真的取值。」

3. **数字改中文读法并补量级**。别念「QPS 3000」，念「三千 QPS」，并补一句量级说明。
   - 「三千 QPS，大概就是单台 MySQL 开始吃紧的量级。」

4. **列举用「第一/第二/第三」，不用 1/2/3**。口语里数数容易乱，「第一第二」更有框架感，也方便面试官记笔记。

5. **每段开头加路标句**。路标句是口语的导航，书面写作里显得啰嗦，但说话时必须有。
   - 开场：「我先说结论」「这个问题我从两个角度看」
   - 中段：「这里有个前提」「再说第二个层面」「展开说一下第二点」
   - 转折：「不过这里有个坑」「这里要分情况」

6. **结尾必须收束**，用「所以我的判断是…」「所以我的做法是…」。禁止开放式结尾——说完就停住，面试官会以为你没想清楚。

7. **主动暴露一处 trade-off**。说得出代价才像真做过。这是区分「背过」和「用过」的分水岭。
   - 「代价是引入了缓存一致性问题，所以我们给缓存设了较短的过期时间兜底。」

8. **英文缩写先说全称再说缩写**，或直接用中文习惯读法。
   - 「TPS」「P99」「QPS」这类可以直接念；「MVCC」「MVCC 多版本并发控制」；生僻缩写第一次出现时补全称。

## 二、时长换算

| 档位 | 时长 | 字数（按 220 字/分钟口播速度） |
|---|---|---|
| `[简答]` | 30 秒 | 约 110 字 |
| `[标准]` | 90 秒 | 约 330 字 |
| `[深挖]` | 180 秒 | 约 660 字 |
| `[深潜]` **口述蒸馏版** | **180 秒** | 约 660 字 |

语速 220 字/分钟是偏快的正常语速。紧张时会更快，所以写稿时按这个标准留 10% 余量。

> ⚠️ **`[深潜]` 档注意**：口述蒸馏版**也是 180 秒 / 660 字，与 `[深挖]` 相同，不要写长。**
> 原因见 SKILL.md「深度释放策略」——真实面试窗口只有 60–120 秒，
> **`[深潜]` 的价值在「追问储备」与「接得住任何角度的追问」，不在口述长度。**
> 1500+ 字的八段正文是**弹药库**，不是**演讲稿**。

## 三、标记符号规范（只用这 4 个）

| 符号 | 含义 | 示例 |
|---|---|---|
| `⏱ 90 秒（约 330 字）` | 段首时长标注 | 放在逐字稿正文第一行 |
| `**加粗**` | 重音词，念时加重 | 「**不能靠把 Prompt 写得更好**」 |
| `…` | 停顿，一个点约 0.5 秒 | 「我先说结论：…工具调用失败是必然的」 |
| `💬 演绎提示：` | 独占一行，说明语速语气，**不念出来** | `💬 演绎提示：这里放慢，咬清楚` |

重音标注密度：每段 2–3 处即可，标太多等于没标。

## 四、开场 / 过渡 / 收尾模板库

### 开场（选一个，不要每次都一样）
- 「我先说结论：**…**」
- 「这个问题我从两个角度看：一是…二是…」
- 「我先确认一下前提：**…**」
- 「这个我有实际踩过坑，我按处理顺序讲。」

### 过渡
- 「再说第二个层面。」
- 「这里有个前提要说明一下。」
- 「不过这里有个坑：**…**」
- 「展开说一下第二点。」
- 「这里要分两种情况。」

### 收尾
- 「所以我的判断是：**…**」
- 「所以我的做法是：**…**，代价是**…**，我们用**…**来兜底。」
- 「以上是我的思路，不知道是不是覆盖了您想问的点。」——适合说完后主动交还话语权

## 五、卡壳救场话术

真到面试现场卡住了，用这些句子争取思考时间，比沉默强得多：

| 场景 | 话术 |
|---|---|
| 完全没思路 | 「这个问题我换个角度，先从**…**说起。」 |
| 想到一半断了 | 「我理一下，这里其实是两个问题：第一…第二…」 |
| 发现自己说错了 | 「我修正一下刚才的说法，**…**更准确。」 |
| 被问到不会的 | 「这块我没在生产上实操过，我的理解是**…**，如果有偏差请您指正。」 |
| 需要时间思考 | 「我稍微组织一下语言。」（比沉默好得多，面试官普遍接受） |

**最重要的一条**：卡壳时不要说「这个我没准备过」。说「这块我没实操过，但我的理解是…」，然后给出一个有理有据的推测——这是加分项，承认不会是减分项。

## 六、口头禅自查

生成逐字稿后自查，出现以下情况需改写：

- 「然后…然后…然后」→ 换成路标句
- 「就是…就是…」→ 直接删，或换成停顿
- 「这个的话」「那个的话」→ 全删
- 一句话里出现两次「因为」→ 拆句
- 结尾用「等等」「之类的」→ 换成明确的收束句

## 七、逐字稿质量自检清单

- [ ] 拿起来能一口气念完，不需要中途换算/回忆
- [ ] 没有括号注释、要点符号、代码片段
- [ ] 每个术语与项目专有名词首次出现都有口语解释
- [ ] 有至少一处 trade-off
- [ ] 结尾是明确的收束句
- [ ] 字数符合档位要求（±10%）
- [ ] 重音标注 2–3 处/段，不过密
